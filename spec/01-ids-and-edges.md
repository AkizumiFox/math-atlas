# 01 識別碼與邊

## 四層加一個概念層

| 層 | 節點 | 量級 | 畫法 |
|---|---|---|---|
| L0 冊 | `F1`、`AN2`… | 25 | 全圖（`generated/volumes.mmd`） |
| L1 章 | `AN2.3` | 172 | 每冊一張圖，另有全套互動圖（`generated/atlas.html`） |
| L2 節 | 由書稿 build 產生 | 推估約 1,800 | 只畫 ego graph |
| L3 陳述 | `an2.thm.metric-compact-equiv` | 推估上萬 | 只畫 ego graph |
| 概念 | 由 revisits／generalizes 連起來的等價類 | — | 概念頁 |

## ID 規則

- **章 ID**：`冊.號`，例如 `AN2.3`。線代各冊沿用線代書的原章號（`LA3.11`），所以 LA 的章號不從 1 開始。一章拆成兩章時加字母後綴（`FA.1a`、`FA.1b`），後面各章的 ID 不動。
- **陳述 ID**：`冊小寫.種類.slug`，例如 `fa.thm.hb-analytic`。種類為 `def | thm | cor | lem | ex | cex | concept | ax`。
- ID **不帶語意**，一經發布就不能刪除。改名或合併時，要在重導表（old → new）留一行，CI 檢查「已發布的 ID 不能消失」。
- 顯示編號（例如「定理 11.5.2」）由 build 根據位置產生，與 ID 無關。

## 邊型別

| 型別 | 縮寫 | 意思 | 無環檢查 | 必讀計算 |
|---|---|---|---|---|
| uses | s | 證明或定義真的需要讀過來源 | 是 | 是 |
| borrows | b | 只把來源的具名結果當黑盒 | 是 | 否（來源列為「只借用」） |
| see | — | 延伸閱讀或動機，可以前向 | 否 | 否 |
| revisits | — | 同一概念的更高 A／R 版本（新 → 舊） | 否 | 否 |
| generalizes／specializes | — | 推廣或特例（陳述層） | 否 | 否 |

規則：

1. **b 的合法性**：被借用的陳述，必須能只用讀者當下作用域裡的記號與術語完整寫出。寫不出來就不是黑盒，應改成 s。讀者對被借用陳述的需要也不能超過 R1（讀懂並套用）。地圖上的代理 lint 見 spec/03 §6.1；完整的記號作用域 lint 由引擎做，見 05。
2. **章層級的邊型別由陳述層彙總**：只要目標章有任一陳述 uses 來源章，就是 s；全部是 borrows 時才是 b。在書稿有 crossref 之前，章層級的邊是計畫值，寫在 `registry/plan-edges.yaml`。
3. **選讀章不能被 s 依賴**：非選讀章不能 s 依賴選讀章。選讀章依賴選讀章可以，例如 F3.3 ← F3.2。
4. **冊內章序必須是 s ∪ b 的線性延伸**：也就是不從後文證明。
5. **傳遞約簡只用於顯示**：registry 與 `atlas.html` 保留所有直接邊；圖上預設只畫約簡後的邊。
6. **每條 b 都要寫 `why`**：說明借用了什麼。這取代了線代書以散文列出的 (A1)–(A7) 清單。
7. **交會章**：若一個結果的陳述需要兩個分支的語彙，它不能以 b 邊借入任何一個分支，而要放進一個位於兩個分支下游的選讀「交會章」。交會章標為選讀，不計入主線統計；冊層級的環與冊序檢查也只看主線，因為交會章本來就會讓冊之間互相指向。**章層級的無環檢查不受影響**，照舊跑含選讀章的完整 s ∪ b 圖：任何章層級的環都代表某個證明在繞圈。例：MA.21b（Löwner 定理的 Pick 形式）、CA.9（Herglotz–Nevanlinna 表示）。

   遇到跨分支的結果，預設先嘗試把章拆開：主線部分留在原章，跨分支的部分放進以字母後綴命名的選讀交會章（例如 CA.8b、ST.6b）；拆不開，才考慮把整章改成 s。

   一條 b 邊因此只有三種結局：宣告 `scope`（陳述的語彙都在讀者作用域內）；改成 s（下游需要 R2 以上，或要操作結果的內部）；搬進交會章（陳述本身跨分支）。

8. **就地定義**：借用章可以自己定義讀懂被借用陳述所需的語彙，但每個就地定義都必須是 `registry/statements.yaml` 裡的一個 def 節點，帶術語欄，並以 `specializes` 指向該術語唯一的正式定義，且限定在它用到的特例上（例如線代書 §6.05 的「連續」只定義 ℂ 的子集上的實值函數，指向 AN1.5）。這樣全套每個術語只有一個 ID，hover 會告訴讀者完整定義在哪裡。條件：
   - 只需要定義，不需要任何定理；
   - 每章至多三個；
   - 讀者只要讀懂就好（就地定義節點的 R ≤ R1）。

   任一條件不符，借用就要改成 s。b 邊的 `scope` 列出借用章自己時，該章必須至少登記一個就地定義。同一術語出現兩個沒有 `specializes` 相連的定義時報錯。

## 計畫邊與計算邊

```
plan-edges.yaml   手寫，章層級，附 why
computed/*.yaml   build 回溯得到（目前只有線代：tools/import_la.py）
      └─ 合併規則：同一對章取最強的型別（s > b > revisits > see）
```

`atlas.py diff` 輸出三份清單（MIPRE blueprint 稽核的教訓）：

- b 被當成 s 使用：計畫寫 b，證明裡卻是硬引用。
- 計畫中有、證明沒用：只檢查兩端都已有書稿的邊。
- 陳述層的 uses 在章層級找不到硬路徑。

## 檢查（`atlas.py check`，失敗時結束碼為 1）

- 所有 ID 都能解析，包括 plan-edges、computed、statements、exam-targets 和 fields。
- s ∪ b 無環。
- 冊內章序是線性延伸。
- 非選讀章不 s 依賴選讀章。
- 每條 b 邊都有 why。
- A／R：uses 邊「需要 ≤ 教到」；borrows 邊需要的 R ≤ R1（陳述層）。
- 記號作用域（代理）：b 邊宣告的 `scope` 章都必須是借用章的 s 祖先。
- 待改寫覆寫（`registry/moves.yaml`）：每一列都要以 `todo` 連到 spec/06 一個未勾選的待辦（`todo:<id>`）；`check` 列出生效中的覆寫數量。書稿改寫完、匯入後某條覆寫不再改變任何引用時，報「過期覆寫」，要求刪掉該列並勾掉待辦。
- 術語：每個術語恰有一個正式定義；就地定義必須是 def、R ≤ R1、每章至多三個。
- 陳述層的 generalizes 跨章時，兩章在章層級必須有邊（任何型別）或 s 路徑相連，避免同一件事的兩個版本各自獨立。

警告（不會讓檢查失敗）：

- 冊層級的環，或冊的排列順序與 s 依賴衝突。
- 約簡後的 s 入度超過 6：Math Academy 所說的「認知塞車」，這種章要考慮拆開。
- 除了 F1.1 以外，沒有任何先修的章。
